# Starjet Mission Control Dark 设计系统（中文版）

版本：1.0
状态：Starjet OCC/SOC 运行类界面的正式设计方向
英文规范：`docs/design-system/starjet-mission-control-dark.md`
CSS 唯一事实来源：`apps/web-ele/src/styles/starjet-mission-control-dark.css`

## 1. 风格定义

这套深色界面称为 **Mission Control Dark（运行指挥中心深色风格）**。它是一套低眩光、高信息密度的专业运行工作界面，视觉来源包括航空公司 OCC/SOC 指挥中心、航电显示、签派工具和专业交易终端。

它不是装饰性暗色主题，也不是游戏 UI、玻璃拟态或赛博朋克界面。视觉语言必须服务于持续监控、精确计时、明确状态和快速异常处置。

适用范围包括：航班计划、机队状态、签派、机组执勤、合规、燃油、地面保障、告警、运行时间线以及相关详情页。

## 2. 设计原则

1. **状态优先于装饰**：颜色必须表达状态或任务类型，不能仅为了“更好看”而增加强调色。
2. **密集但平静**：在有限空间内展示更多运行信息，同时避免厚重卡片、过多阴影和大面积留白。
3. **上下文持续可见**：日期、飞机、时间基准、筛选条件和当前选中任务应在操作过程中保持可见。
4. **异常驱动层级**：正常信息保持克制；警告、冲突和当前时间标记拥有最高对比度。
5. **两秒内完成扫描**：无需打开详情页即可识别注册号、航段、UTC 时间、状态和下一步行动。
6. **精确胜过柔和**：使用细分隔线、紧凑控件、克制圆角、对齐数据和最少层级阴影。

## 3. 视觉特征

- 接近黑色、略带冷蓝倾向的底色。
- 各层表面通过轻微明度差区分，不使用大面积彩色区块。
- 使用 1px 分隔线和网格线组织工作区。
- 中文和普通界面文字使用无衬线字体；时间、代码、编号和数值使用等宽字体。
- 蓝色表示导航、选中和信息。
- 亮绿色表示就绪、已确认、可用或主要运行操作。
- 琥珀色表示待处理、需要关注或准备度下降。
- 红色表示冲突、逾期、受阻或不安全。
- 紫色专用于维修或工程任务，不用于普通强调。
- 青绿色用于调机、摆渡或辅助性移动任务。
- 光晕仅用于键盘焦点、当前选中项和实时状态标记。

## 5. 字体系统

### 字体家族

- 普通界面和中文：`Inter`、`SF Pro Display`、`PingFang SC`、`Microsoft YaHei`、系统无衬线字体。
- 运行数据：`JetBrains Mono`、`SFMono-Regular`、`Roboto Mono`、系统等宽字体。

机场代码、飞机注册号、航班 ID、UTC 时间、持续时间、百分比、计数器和坐标使用等宽字体。长中文标签和说明文字不要使用等宽字体。

### 字号层级

| 角色 | 字号 / 行高 | 字重 |
| --- | --- | --- |
| 微型元数据 | `11 / 16px` | 500 |
| 辅助说明 | `12 / 18px` | 500 |
| 正文 / 数据 | `13 / 20px` | 500 |
| 控件标签 | `14 / 20px` | 600 |
| 区域标题 | `16 / 24px` | 650 |
| 面板数值 | `20 / 28px` | 700 |
| 主要运行 KPI | `24 / 32px` | 700 |

全大写英文眉题可使用 `0.08em`–`0.12em` 字间距；中文或长数值不要增加字间距。

## 6. 间距、几何与层级

- 基础间距单位：`4px`。
- 标准间距：`4、8、12、16、20、24、32px`。
- 紧凑控件高度：`32px`；标准控件高度：`36px`；主要操作按钮：`40px`。
- 普通面板内边距：`16px`；大型区域：`20px` 或 `24px`。
- 表格或时间线行最小高度：`48px`；飞机时间线行通常为 `96px`–`120px`。
- 圆角：标签 `4px`，控件和卡片 `6px`，面板 `8px`，大型弹层最多 `12px`。除紧凑状态标签外避免胶囊形状。
- 默认边框为 `1px`；选中任务可以使用 `2px` 蓝色边框。
- 阴影只用于浮层和选中任务。导航栏和通栏区域禁止使用大面积柔和阴影。

## 7. 页面架构

桌面端应优先采用连续的运行指挥工作区，而不是由大量独立卡片组成的仪表盘：

```text
指挥栏：产品/上下文 | 视图/日期控件 | 时间基准/操作
指标带：计划任务 / AOG / 保障异常 / 冲突 / 放行率
工作区：
  机队栏 | 主时间线或表格画布 | 上下文检查器
```

推荐桌面尺寸：

- 指挥栏高度：`56px`–`64px`。
- 指标带高度：`64px`–`72px`。
- 机队栏宽度：`240px`–`280px`。
- 右侧检查器宽度：`360px`–`420px`。
- 主画布：填满剩余宽度和高度。

主画布通过网格线和空间对齐建立秩序，不要叠加多层卡片。页面外边距保持在 `12px`–`20px`，避免在运行工作区周围产生大面积空白。

### 响应式行为

- `>= 1440px`：同时显示机队栏、主画布和右侧检查器。
- `1200–1439px`：机队栏缩至 `220px`–`240px`，检查器缩至 `320px`–`360px`。
- `960–1199px`：检查器变为抽屉，机队栏可以折叠。
- `< 960px`：显示聚焦式单面板视图，保留任务、日期和状态上下文，不能只是把三栏整体缩小。

运行桌面的主要目标宽度是 `1280px` 及以上。时间线内部允许横向滚动，整个应用外壳禁止产生横向滚动。

## 8. 核心组件

### 指挥栏

- 使用 `--sj-surface-1` 的单层横向区域。
- 产品标识保持紧凑，运行筛选和上下文优先。
- 分段控件使用克制边框；当前视图使用 `--sj-surface-3` 和 `--sj-text-1`，不要做成高亮填充的大按钮。
- 主要运行操作使用亮绿色，普通导航使用蓝色。

### KPI 指标带

- 数值大于标签，并保持共享基线对齐。
- 各指标之间使用 `1px` 垂直分隔线。
- 数值或标签前使用 `6px`–`8px` 状态点。
- 正常指标保持中性，语义色只应用于状态点或异常数值。

### 时间线与日期头

- 时间线纵向滚动时，日期头保持吸顶。
- 今天使用克制的浅色底和亮绿色“今天”标签。
- 当前时间使用 `1px` 红色线和紧凑红色时间标签。
- 时间文字使用等宽字体并降低层级；网格线对比度必须低于任务卡边框。

### 机队 / 飞机行

- 注册号作为主信息，机型和基地作为辅助信息。
- 准备度条根据阈值使用亮绿色、琥珀色或红色。
- 状态文字放在注册号附近，不能只依靠颜色表达准备度。

### 航班任务卡

- 最小可用宽度：`128px`；推荐宽度：`160px`–`240px`。
- 高度随内容变化，通常为 `64px`–`84px`。
- 第一行：任务类型标签 + 起点或航向。
- 第二行：UTC 时间范围。
- 选中卡片：`2px` 蓝色边框和克制蓝色光晕。
- 底色使用低透明度任务色或状态色，正文保持高对比度。
- 航段和关键时间在可通过换行获得空间时不得截断；至少显示两行后才能省略。

### 上下文检查器

- 大屏固定在右侧，窄屏变为抽屉。
- 顶部先显示选中航班和航段，再依次展示保障链、机组执勤和告警。
- 区域标题使用小号大写英文或双语标签，并配细分隔线。
- 正常条目保持扁平，不要把每一行再包成独立卡片。
- 底部放置整宽的亮绿色“下一步安全操作”。破坏性或不安全操作使用红色并要求确认。

### 表格与列表

- 表头使用 `--sj-surface-2`；行底色只做一级明度交替。
- 行高为 `44px`–`52px`。
- 代码和时间按照等宽网格对齐。
- 悬停使用 `--sj-surface-3`；选中行增加蓝色左边线。

### 状态标签

- 高度 `20px`–`24px`，圆角 `4px`，水平内边距紧凑。
- 使用语义色文字、浅色底和可选图标或状态点。
- 每个标签必须包含可读文字，如“已确认”“待处理”“异常”“受阻”；颜色不能成为唯一信息载体。

## 9. 交互状态

- 悬停：表面明度提高一级，不移动组件。
- 激活或选中：蓝色边框或下划线，加轻微蓝色底。
- 键盘焦点：`2px` 蓝色焦点环，外偏移 `2px`。
- 禁用：降低对比度并移除光晕，同时保持标签可读。
- 加载：在现有布局内使用骨架屏；首次加载后不能把整个指挥面清空。
- 空状态：说明当前筛选和日期上下文，并提供一个相关恢复操作。
- 错误：保留周围运行上下文，只在失败区域展示准确错误和重试指引。

动效应短且具有功能性：悬停 `120ms`，选中 `160ms`，抽屉 `200ms`。必须遵守 `prefers-reduced-motion`。

## 10. 数据与文案规则

- 机场代码使用大写 ICAO：`ZSPD`、`ZGGG`。
- 飞机注册号使用大写和连字符：`B-9308`。
- UTC 时间使用四位数字加 `Z`：`1330Z`；本地时间必须明确标记 `LT`。
- 中文界面日期使用“8月21日”；密集元数据可以使用 `21 AUG`。
- 航段使用 `ZSPD → ZGGG`；需要更强方向提示时使用项目现有图标库。
- 避免只有“处理中”而没有负责人、截止时间或下一步操作的模糊状态。
- 双语标签只用于运行团队确实需要的场景，不要为每个普通控件重复英文。

## 11. 无障碍要求

- 主要文字与背景的对比度必须达到 WCAG AA。
- 关键说明不能只使用低对比度辅助文字。
- 状态必须在颜色之外包含文字或图标。
- 所有交互控件都必须有清晰的键盘焦点样式。
- 最小鼠标点击区域为 `36 × 36px`；触屏布局使用 `44 × 44px`。
- 时间线任务卡的无障碍名称必须包含类型、注册号、航段、时间和状态。
- 禁止关闭浏览器缩放；必须测试 200% 缩放和减少动效模式。
- 吸顶区域不能遮挡当前获得焦点的内容。

截图检查无法证明键盘顺序、屏幕阅读器输出、精确对比度或缩放行为，这些必须通过实际实现测试。

## 12. AI 实现契约

任何生成或修改 Starjet 运行界面的 AI 和开发者，都必须按以下顺序工作：

1. 修改 UI 前先阅读本文件和 CSS 令牌文件。
2. 明确运行人员的主要判断、当前上下文、异常以及下一步安全操作。
3. 先确定运行指挥工作区布局，再添加组件。
4. 优先复用项目已有的 Starjet 组件和图标。
5. 此视觉系统只使用 `--sj-*` 令牌。
6. 实现悬停、选中、焦点、加载、空状态和错误状态。
7. 验证 `1440px`、`1280px` 和 `1024px` 宽度。
8. 交付前检查对比度、键盘焦点、溢出、吸顶区域和长中文文本。

### AI 必须说明的内容

在提出或实现页面时，AI 必须说明：

- 运行人员的主要任务。
- 页面持续显示的上下文。
- 每一种强调色的语义含义。
- 侧栏、检查器和时间线或表格的响应式行为。
- 复用了本系统中的哪些组件和令牌。

### 应该这样做

- 使用接近黑色的分层表面、细分隔线、紧凑控件和清晰对齐。
- 只为当前、选中、就绪、警告和严重状态保留高亮。
- 始终展示飞机、航段、日期、UTC 时间和准备度。
- 优先使用连续运行画布，而不是大量独立仪表盘卡片。

### 禁止这样做

- 禁止引入玻璃拟态、渐变、装饰性霓虹或重度模糊。
- 禁止在深色工作区中加入大面积圆角白色卡片。
- 禁止同时把蓝色用于选中和所有主要操作按钮。
- 禁止用红色做中性强调。
- 禁止默认用省略号隐藏关键航段和时间。
- 禁止给导航栏或吸顶区域添加大阴影。
- 已有令牌时，禁止新增原始颜色、间距或圆角数值。

## 13. 评审清单

- [ ] 整个运行工作区统一使用深色表面层级。
- [ ] 主要操作、选中、就绪、警告和严重状态具有不同语义。
- [ ] 所有代码和时间使用运行数据等宽字体。
- [ ] 网格、行、卡片和面板遵守 `4px` 间距系统。
- [ ] 没有无意义的嵌套卡片、渐变或超大阴影。
- [ ] 滚动时当前日期、当前时间和选中任务保持可见。
- [ ] 长航段和中文文本能够换行或重排，不隐藏关键数据。
- [ ] 所有交互控件有键盘焦点，所有状态都有非颜色标签。
- [ ] 页面在 1440、1280 和 1024 宽度下表现正确。
- [ ] 已覆盖加载、空状态、错误、禁用、悬停和选中状态。

## 14. 项目接入方式

在运行工作区根节点添加以下任一标识：

```html
<div class="sj-mission-control">...</div>
```

或：

```html
<div data-starjet-theme="mission-control-dark">...</div>
```

然后只使用 `apps/web-ele/src/styles/starjet-mission-control-dark.css` 中的 `--sj-*` 变量。英文版和中文版描述不一致时，以 CSS 令牌文件和最新版本号为准，并同步修正两份文档。
